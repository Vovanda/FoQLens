Precision where the question is, not everywhere

A question about biology and a question about a proof do not need more or less precision. They need precision in different places.

Every quantization scheme decides precision per fixed unit - the model, a layer, a channel, a token, an expert. The boundaries come from the architecture; a controller only picks how many bits each unit gets.

FoQLens asks the model itself which weights matter for this query, places those blocks on a map, and reads the rest coarsely. Mixture of Experts is the rigid special case of the same idea: experts with hard edges, fixed at training, opened by a router.

The mechanism is FoQZones - focusable quantization zones. Call it a Mixture of Zones if you like, though there is no router here and there will not be one. FoQLens is the project and the model that carries the regulator; the lens is the picture of it.

The metaphor above is drawn on real weights: the map of Gemma 4 E2B, 14 708 blocks of 64 output rows, blocks that light up together lying close. Place a zone on it and the regulator runs - the plate gives the cost in bits per weight.

Coarse pixels are weights read at few bits; sharp ones are read at many. Memory is not a budget you set - it is what your zones cost.

The mechanism

Three controls, each doing one thing: the base precision - what the whole network is read at before any zone is lifted, called floor in the runs and the scripts; focus area - how large the zones are; focus strength - how far their centers rise above it. The rules below are what the field above runs; the full text is in docs/lens.md.

The rules need a distance d between blocks; today it is the distance on the weight map drawn above. In what space the zones of a query live, and what makes two weights close, is an open question of the problem statement.

ladder      ℓ₀ < ℓ₁ < … < ℓ_m          the levels this model can be read at; ℓ₀ = ZERO
base        G = ℓ_γ                     any rung; floor in the scripts
distance    d(a, b)                     between blocks; the weight map today, the space is open

1 radius    R_i = r_i · f / (1 − f)
2 ceiling   κ = γ + ⌊g · (m − γ)⌋       g = 0: the lens is the base;   g = 1: the top rung
3 profile   stops s_κ < … < s_(γ+1)     where each ring ends, in radii
4 lift      ρ_i(b) = d(b, c_i) / R_i,   L_i(b) = max(0, 1 − ρ_i(b) / s_last)
5 combine   L(b) = min(1, Σ L_i)  or  max L_i
6 level     ρ* = s_last · (1 − L(b))    the ring that ρ* falls into; outside every lens: G
7 memory    bits = Σ w_b · bits(b) / Σ w_b

Nothing here names a level: the ladder comes from the model and its storage. On Gemma 4 E2B one stored copy of residual slices is read at 2, 4, 6 or 8 bits, and the stored weight itself is the rung above them - so the ladder is ZERO, D2, D4, D6, D8, bf16, and the regulator runs over all six.

What is claimed

Each is fixed in git as a direction before the run that tests it. None is settled: the bench reached a point where its own test set could not tell a layout from a coin toss, so every verdict was withdrawn and the list went back to untested.

IdClaim
H1The mask of a query is separable by topic and concentrated - there is an address to read at alluntested
H2Zones of related topics overlap more than zones of unrelated onesuntested
H3Precision laid out by the query beats uniform quantization at the same memoryuntested
H4The main one. A draft read mostly at base precision, then refined with sharper zones, ends better than the same model at native precision - where there are iterations: an agent or a model's reasoninguntested
H5A horizon. A network trained with zoning and read with FoQZones beats a Mixture of Experts trained the classical way on the same data, holding no more in memory at any momentuntested
H6An additional one. How good asking for a shorter answer and coarsening the weights each are at holding knowledge in compressed form - and below which step coarsening slides into nonsenseuntested

The full list, with the experiments behind each: docs/hypotheses.md.

The corpus being built now

A layout can only be measured where the model answers from knowledge. So the questions are selected by measurement: a question stays if the full model answers it right in its own words. It never sees options, in any regime, and three judges read its answer - the SQuAD score, the full model itself, and Claude.

RegimeWhere the answer isWhat the zones should do
Readingin the passage - SQuAD v2little: the knowledge came in with the prompt
Knowledgeonly in the weights - TriviaQA, NQ-open, ARC-Challenge without its optionsdecide - the regime the idea is about
Two stepssplit across two passages - HotpotQAmatter, and less than in the second

If the lenses help as much where the answer sits in the context as where it is only in the weights, the mechanism is not doing what it claims - and that is the test the old corpus could not run. How a corpus is chosen: docs/corpus.md.
